# Contributing to Paper Preflight

Thanks for helping! The most valuable contributions are usually small:

- **Verifying or adding a venue preset** (one JSON file).
- **Reporting a false positive / false negative** with a minimal PDF that reproduces it.
- **Improving translations** in `src/i18n.ts`.

Please do not attach real submissions or anything that identifies an author to issues. Create a small
synthetic PDF instead (see `scripts/make_fixtures.py` for examples).

## Venue presets

1. Add or edit `presets/<id>.json` (`id` must equal the file name, kebab-case). The format is described
   in the README and in `presets/schema.json`.
2. Take values from the **official** call for papers or author kit and put that link in `cfpUrl`.
3. If you confirmed every value, set `"unverified": []` and `"lastChecked": "YYYY-MM-DD"`.
   Otherwise list the fields you could not confirm in `unverified`. Never guess a number without
   listing it there.
4. Mention the edition (`"edition": "2026"`) — limits change between years. When a venue changes its
   rules, update the existing file rather than adding a second one, unless both editions are relevant.
5. `npm test` must pass (the preset test validates every file).

In the PR description, quote or link the sentence of the CFP that states each value.

## Code

```bash
npm install
npm run dev
npm test            # vitest
npm run build
npm run test:e2e    # Playwright against dist/ (needs Chromium: npx playwright install chromium)
```

- The analysis core in `src/core/` must stay free of DOM access and of network calls. Checks take a
  `DocModel` and return findings with an i18n `code`, optional `params`, `page` and `evidence`.
- Every new finding code needs an English **and** Chinese string in `src/i18n.ts`
  (`tests/unit/i18n.test.ts` enforces this).
- Add unit tests for new heuristics, including at least one case that must *not* be flagged.
- Do not add runtime dependencies on external services or CDNs. Privacy is the core feature.
- Keep the UI usable at phone width and in both light and dark themes.

## Fixtures

`tests/fixtures/*.pdf` are generated by `npm run fixtures`
(Python 3 with `reportlab`, `pypdf`, `matplotlib`). All names and addresses in them are fictional.
Commit regenerated fixtures together with the test changes that need them.

## Commit / PR

- One topic per pull request; describe what changed and how you tested it.
